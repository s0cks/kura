## View

The View is the window: the root of every view. Kura makes it, and the program can't: there is no `#view` to write.
Writing one is an error. It has the box properties and the container properties, so it can be given a background, a
padding or a direction with a `set view` rule, at the top level of a file or before the body of `view`:

```kura
set view(fill: white, padding: 16px, direction: "column")

fn view(state: State): Node =>
  #text("Hello")
```

```kura
fn view(state: State): Node =>
  set view(fill: white)
  #text("Hello")
```

Without a rule the view still has its View, with nothing to paint. A `set view` rule anywhere else is an error, since
there is only one View and it is the same for all of `view`.

The program is run in its view: `init`, `update` and `view` are given it, as a `this` that they don't name and take no
parameter for, and what belongs to the view (its layout, its inputs, where its elements are) is kept in it.

    Background fill color of the box.

  </Property>
  <Property name="border-width" types={["Px"]}>

  </Property>
  <Property name="radius" types={["Px"]}>

  </Property>
  <Property name="tooltip" types={["String"]}>
    A tooltip: text that is shown next to the pointer once it has been over the box for a moment (half a second, unless
    the host says otherwise), over everything else. What is inside the box has the box's tooltip unless it has its own, and
    where the box is cut off, by a `#scroll` for instance, it has none. A click or the wheel hides it until the pointer
    is over something else. The text can be made when the view runs, like `"{count} items"`, and wraps if it is long.
  </Property>
  <Property name="opacity" types={["Number"]}>
    Opacity from `0` (transparent) to `1` (opaque). It lightens the box's own fill and border, or a text's color. It
    is not passed on to what is inside the box.
  </Property>
  <Property name="on-click" types={["Message"]}>
    Message dispatched when the box is clicked.
  </Property>

## Text

A <Node name="box" /> for displaying text

<PropertyTable inherits={"box"} >
  <Property name="value" types={["String"]}>
    What to show.
  </Property>
  <Property name="size" types={["Px"]}>
    The font size, in `px` (`>= 0`).
  </Property>
  <Property name="font-family" types={["String"]}>
    The font: a name, or a comma-separated list in order of preference.
  </Property>
  <Property name="color" types={["Color"]}>
    The color of the text. Opaque black if it isn't given.
  </Property>
  <Property name="text-align" types={["String"]}>
    Horizontal text alignment: `"left"`, `"center"`, or `"right"`. Each line of the text is placed in the room the
    text has, which is its own width unless something makes it wider, like a column that stretches it. It is
    a word, not a value that changes.
  </Property>
  <TableSeparator text="Positional Arguments"
                  color="primary" />
  <Property name="value"
            types={["String"]}>
    The text to render
  </Property>
</PropertyTable>

<Example>

```kura
#text(size: 24px,
      font-family: "Inter, sans-serif",
      color: white,
      "Hello World")
```

</Example>

<Aside>

`font-family` is a constant string, like `size`, because text is measured before the view runs.
The renderer finds the first family in the list that is installed on the system, and uses the system's
default font when none is. Text wraps at word boundaries to the room its box has, and is laid out and drawn
with the same measurements.

</Aside>

## Input

A single-line <Node name="box" /> for user input.

<PropertyTable inherits={"box"}>
  <Property name="size" types={["Px"]}>
    The font size, in `px` (`>= 0`).
  </Property>
  <Property name="font-family" types={["String"]}>
    The font: a name, or a comma-separated list in order of preference.
  </Property>
  <Property name="color" types={["Color"]}>
    The color of the input text.
  </Property>
  <Property name="text-align" types={["String"]}>
    Horizontal text alignment: `"left"`, `"center"`, or `"right"`.
  </Property>
  <Property name="placeholder" types={["String"]}>
    What is shown, dimmed, while the input is empty.
  </Property>
  <Property name="readonly" types={["Bool"]}>
    An input that is `readonly` can be selected from and copied, but not changed. Default `false`.
  </Property>
  <Property name="on-input" types={["Message"]}>
    The variant that the text goes in when the user changes it: `on-input: UpdateQuery` sends
    `UpdateQuery("the new text")`, so `UpdateQuery` has to carry a `String`. An input without an `on-input`
    has nowhere to send a change, so it is read-only.
  </Property>
  <TableSeparator text="Positional Properties" />
  <Property name="value" types={["String"]}>
    The text in the input.
  </Property>
</PropertyTable>

<Example>

```kura
type Message = UpdateQuery(String)

fn update(msg: Message, state: State): State =>
  match msg {
    UpdateQuery(text) => { state | query: text }
  }

fn view(state: State): Node =>
  #input(:search,
         size: 16px,
         padding: 8px,
         border-color: #444444,
         border-width: 1px,
         placeholder: "Search...",
         on-input: UpdateQuery,
         state.query)
```
</Example>

An input is controlled: the view's `value` is the text, and a change is a Message that goes through `update` and
comes back as the next `value`. If `update` doesn't take the change, the text goes back to what it was. What the
program has no say in is which input has the keyboard (an input is clicked to get it, and Escape or a click elsewhere
gives it up), where the caret and the selection are, and how far a long text is scrolled to keep the caret in view.

An input is one line, 200px wide unless it is given a `width` (or grows), and as tall as a line of text with its padding.
`padding` is 4px unless it is given.

<Aside>

Like `#text`, `font-family` and `size` are constants used to measure text metrics prior to layout.

</Aside>

A host sends what is typed with `Session::TextInput` and the editing keys with `Session::KeyDown`; see the
[MVU guide](/kura/guides/mvu/).

## Scroll & List

A <Node name="container" /> for displaying more children than fit. What is in it is laid out at its own size, and
the box shows the part of it that has been scrolled to, clipping the rest. Its `padding`, `gap`, `direction`, `align`
and `justify` are for what is inside it, and its `width`, `height`, `fill`, `border-*` and `radius` for the box.

A `#list` is a `#scroll` that goes down: its `direction` is `"column"` unless it says otherwise. Every row of a list is
laid out and drawn, whether it is in view or not.

The host scrolls it (`Session::Scroll`, or `kura_rt_event_scroll`): the wheel moves the topmost container under the
pointer that has room to go that way, and when it is as far as it goes the one it is in gets the wheel. How far a
container is scrolled is kept from one frame to the next, and is kept in range if its content shrinks.

<PropertyTable inherits={"container"}>
  <Property name="on-scroll"
            types={[ "Message" ]}>
    Message dispatched when the scroll offset changes. It doesn't say where the offset is yet.
  </Property>
</PropertyTable>

<Example>

```kura
#scroll(height: 300px,
        direction: "column",
        gap: 8px,
        on-scroll: Scrolled) {
  #text(value: "Item 1", size: 14px)
  #text(value: "Item 2", size: 14px)
}
```

</Example>
